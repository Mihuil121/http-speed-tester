# Ответы на сопутствующие вопросы для формы отправки

### 1. «Как ты использовал ИИ при решении?»
**Ответ:**
ИИ использовался как высокопроизводительный инженерный ассистент для ускорения рутинных операций и проектирования чистой архитектуры решения:

- **Архитектурный дизайн:** ИИ помог четко разграничить ответственность между ядром бизнес-логики (`benchmark.js`) и CLI-интерфейсом (`index.js`), обеспечив высокий уровень тестируемости кода (Dependency Injection для `fetch`).
- **Синтаксис и API:** Проверка точного поведения встроенного API `node:test`, `node:assert/strict` и `ArrayBuffer` в Node.js 18+ без привлечения внешних библиотек.
- **Тестирование:** Генерация кейсов для мока `fetch` и обработки краевых случаев (частичные падения запросов, 404/500 ошибки).
- **Документирование:** Форматирование Markdown, подготовка структурированного `README.md` с математическими формулами.

---

### 2. «Что бы улучшил, будь у тебя больше времени?»
**Ответ:**
Если бы у меня было больше времени для развития проекта, я бы реализовал следующие улучшения:

1. **Гибкая конфигурация CLI:** Использование `commander` или `yargs` для поддержки флагов CLI:
   - `-n, --count <number>` — количество запросов.
   - `-c, --concurrency <number>` — возможность сравнить последовательное и параллельное скачивание.
   - `-H, --header <key:value>` — кастомные HTTP-заголовки.
   - `-t, --timeout <ms>` — таймаут ожидания соединения (через `AbortController`).
2. **Статистика и перцентили:** Расчёт медианы, минимального/максимального времени, а также перцентилей (p50, p95, p99) для точной оценки стабильности сети.
3. **Интерактивный UI:** Визуализация прогресса в реальном времени с помощью прогресс-бара (`cli-progress` или `ora`).
4. **Форматы экспорта:** Добавление возможности выгрузки отчётов в JSON, CSV или HTML для интеграции в системы мониторинга или CI/CD.
5. **Повторные попытки (Retries):** Реализация логики Exponential Backoff при временных сетевых сбоях или ответах сервера 429/5xx.
